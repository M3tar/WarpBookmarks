# 传送书签：开发计划

> 原则：每个阶段都先在 Windows 目标环境构建和实机验证，再进入下一阶段。

## 阶段 0：运行时探针与工程基线

目标：用游戏 1.6.15 的真实对象验证所有关键假设。

- 建立 `net6.0` SMAPI 工程、manifest、英文/简中 i18n；
- 建立安全 Windows 构建/安装脚本；
- 探测普通室外、室内、多个同类型畜棚、鸡舍、小屋、移动建筑和自定义地图的稳定位置字段；
- 验证每位 `Farmer` 的稳定身份与 `modData` 持久化；
- 验证通行、占用、地图边界和事件状态 API；
- 建立 `wb_where`、`wb_validate_location`、`wb_validate_tile`；
- 不制作正式 UI，不承诺最终字段。

验收：得到 Windows 单人和双人联机的探针日志，明确位置身份与持久化方案。

## 阶段 1：单人传送内核

- 当前地点记录；
- 返回住宅；
- 原版五种标准传送图腾默认目的地提供器；
- 自定义书签创建、编辑、删除；
- 统一安全传送管线；
- 上一个位置 A ⇄ B；
- 睡觉、昏迷、读档与返回标题清理；
- 原版普通地图和重复建筑验证；
- 暂用最小测试菜单或命令，不做视觉收尾。

验收：单人档连续跨天使用，无错误传送、无失效历史、无存档异常。

## 阶段 2：传送手册 UI

- 羊皮纸三栏主界面；
- 分类、搜索、滚动、详情；
- 收藏和固定排序；
- 创建/编辑/删除与撤销；
- 鼠标、键盘、手柄导航；
- 已确认的 K 与 Shift+K 默认快捷键、旧测试配置迁移、输入抑制及动态提示；
- GMCM 可选集成；
- UI 缩放和中英文文本测试。

验收：参考 `MultiplayerNpcLocator` 的实机截图流程检查色带、遮挡、裁切、焦点和快捷键穿透。

## 阶段 3：精准坐标与失效修复

- 地图选择器和高级内部名称输入；
- 多格式坐标解析与预览；
- 当前坐标显示和复制；
- 仅传送/另存为书签；
- 失效原因、重新绑定；
- 地图缺失和安全格修正反馈；
- 已访问地图/权限策略按最终产品决策落地。

验收：合法、越界、占用、缺图、未访问、特殊地图和恶意/异常输入均有确定结果。

## 阶段 4：联机个人化兼容

- 主机与加入者各自独立书签；
- 每位玩家独立住宅和上一个位置；
- 多人落点占用处理；
- 联机菜单不暂停提示；
- 未安装 Mod 的玩家兼容；
- 断线、重连、改名、移动小屋和换设备边界验证；
- 不加入共享、邀请和队伍传送协议。

验收：双人联机双方列表互不影响，重连后各自数据正确，多人同时传送无重叠或异常。

## 阶段 5：兼容性收尾

- 默认地点收藏、隐藏、恢复和版本更新收尾；
- 严格解锁条件和营业/房间策略收尾；
- SVE 与常规自定义地图实测；
- 与 NPC Locator 同时安装验证。

## 阶段 6：发布准备

- README、简中 README、CHANGELOG、已知限制；
- Release 构建、安装、更新和打包脚本；
- 包内只包含所需 DLL、manifest、i18n 和发布文档；
- 输出 SHA-256；
- 完成单人、主机、加入者最终冒烟；
- 检查 SMAPI 日志没有本 Mod 未处理异常；
- 验证卸载后存档可正常继续，并说明遗留 `modData` 的处理方式。

## 暂缓到首版之后

- 世界地图图钉；
- 批量导入/导出书签；
- NPC 当前区域入口；
- 更复杂的图标包或自定义资源；
- 与其他 Mod 的公开 API；
- Mac/Linux 正式验证矩阵。
